# UI Density v1

## Densidad general

- Objetivo: `medium operational density`.
- La UI no debe sentirse vacia ni de showroom.
- Tampoco debe sentirse cargada como ERP tradicional.

## Superficies

- Base visual dark gray, no pure black.
- Paneles con contraste sutil y bordes minimos.
- Color solo para estados semanticos y focos de navegacion.
- Evitar cards gigantes de colores o dashboards arcoiris.

## Tipografia

- `Helvetica Neue` como primaria.
- Jerarquia corta y clara.
- Pocos pesos tipograficos.
- Texto principal near-white; secundario muted gray.

## Listas y tablas

- Patron central del producto.
- Row height default: `48px`.
- Variant mas densa para operaciones: `44px`.
- Header de tabla: `40px`.
- Maximo recomendado visible sin overflow: `6-7 columnas`.
- Primera columna siempre prioriza identidad: nombre + codigo.
- Hover sutil, sin zebra stripes fuertes.
- Status chips compactos, no badges gigantes.
- Filtros arriba, no side panels eternos por defecto.
- Sticky header en tablas largas.

## Detail panes

- Summary header arriba con estado actual y quick actions.
- Tabs o secciones claras: `Overview`, `Timeline`, `Incidents`, `Files`.
- Action rail lateral solo cuando aporte velocidad real.
- Timeline con lectura vertical limpia, no feed desordenado.

## Dashboard

- Un strip corto de KPIs.
- Dos o tres queues operativas maximo.
- Un bloque de movimientos recientes.
- No mosaico de doce widgets pequenos.
- Cada card debe responder una accion o decision real.

## Spacing

- Padding de panel: `16-20px`.
- Gap entre bloques principales: `16px`.
- Forms con grupos claros y pocas columnas simultaneas.
- Evitar formularios largos de una sola columna infinita.

## Color logic

- Seleccion: un accent frio y sobrio.
- Warning: ambar moderado.
- Critical: rojo controlado, no neon.
- Success: verde muted.
- Los colores semanticos no deben tenir pantallas enteras; solo puntos, chips, iconos o acentos finos.
